# ADR-003: Модель учёта исключённых месяцев при расчёте прогноза



## Контекст и постановка задачи



Пользователь должен видеть реалистичный прогноз ежемесячного взноса (REQ-FUNC-004). Если пользователь заранее знает, что в какие-то месяцы он не сможет откладывать (отпуск, крупные траты), он должен иметь возможность исключить их при создании цели (REQ-FUNC-013). Система должна динамически пересчитывать требуемый ежемесячный взнос, деля остаток не на все месяцы, а только на «активные».



## Драйверы решения



- Повышение точности прогнозирования для пользователя.

- Обеспечение гибкости при редактировании цели.

- Единый алгоритм для расчёта на экране цели и в сводке.

- Безопасность типов для денежных расчётов (CON-05, REQ-REL-003).



## Рассмотренные варианты



1. Хранение исключённых месяцев в отдельной таблице `ExcludedMonth`, связанной с `Goal`.

2. Хранение исключённых месяцев в виде строки CSV внутри сущности `Goal`.

3. Отсутствие исключённых месяцев (деление остатка на все календарные месяцы).



## Итог решения



Выбран вариант 1. Создаётся отдельная сущность `ExcludedMonth` с полями `(goal\_id, month YYYY-MM)`. При расчёте прогноза алгоритм вычисляет `activeMonths = totalMonths - excludedMonths` (учитываются только месяцы в диапазоне от текущего до целевой даты). Ежемесячный взнос = `Остаток / activeMonths` с округлением `HALF\_UP`. Если `activeMonths = 0`, прогноз не рассчитывается и выводится предупреждение.



### Последствия



- Нормализованная структура данных упрощает запросы и обеспечивает уникальность месяца в рамках одной цели.

- Усложняется логика удаления: при удалении цели каскадно удаляются её исключённые месяцы (REQ-FUNC-002).

- Требуется обновление UI-форм для выбора месяцев.



### Подтверждение



Модульные тесты проверяют расчёт взноса при различных комбинациях исключённых месяцев (0, 1, все), корректность обработки дат (месяцы в прошлом игнорируются) и сценарий с `activeMonths = 0`.



## Плюсы и минусы вариантов



| Вариант | Плюсы | Минусы |

|---|---|---|

| Отдельная таблица | Нормализация, простота запросов, уникальность месяцев | Дополнительный join при выборке |

| CSV-строка в Goal | Меньше таблиц | Сложные запросы, нет约束 уникальности |

| Без исключений | Простота | Не соответствует REQ-FUNC-013 |
