# ADR-002: Использование локальной СУБД SQLite для хранения данных



## Контекст и постановка задачи



Приложение «Копилка целей» является полностью автономным и должно работать без подключения к интернету (CON-04, REQ-SEC-001). Данные пользователя (цели, пополнения, исключённые месяцы) должны храниться локально (CON-03) с гарантией транзакционности (REQ-REL-001) и поддержкой до 100 целей и 10 000 пополнений (A4). Необходимо выбрать формат локального хранилища.



## Драйверы решения



- Обеспечение ACID-транзакций для защиты от потери данных при сбоях.

- Поддержка индексов для быстрой фильтрации и сортировки (REQ-PERF-002).

- Возможность создания резервных копий (REQ-FUNC-009).

- Нулевая стоимость и открытый исходный код (CON-07).



## Рассмотренные варианты



1. Встраиваемая реляционная СУБД SQLite (через JDBC).

2. Хранение данных в текстовом формате JSON.

3. Встраиваемая NoSQL БД (например, H2 или Realm).



## Итог решения



Выбран вариант 1. Данные хранятся в локальном файле SQLite. Доступ к данным осуществляется через слой репозиториев (REQ-INT-006). Схема данных версионируется, при обновлении приложения выполняются миграции (REQ-CM-002).



### Последствия



- Транзакционность гарантирует, что при аварийном завершении приложения данные не будут потеряны (REQ-REL-001).

- SQL-запросы позволяют эффективно вычислять агрегаты (суммарный прогресс, остаток).

- Требуется JDBC-драйвер SQLite.



### Подтверждение



Тесты проверяют атомарность записи (имитация сбоя), корректность миграций схемы и скорость выборки при 10 000 записей.



## Плюсы и минусы вариантов



| Вариант | Плюсы | Минусы |

|---|---|---|

| SQLite | ACID, SQL-запросы, индексы, единый файл для бэкапа | Требует JDBC-драйвера, схему нужно мигрировать |

| JSON-файл | Простота реализации | Нет транзакций, риск потери данных при сбое записи, медленная фильтрация |

| NoSQL (H2/Realm) | Гибкая схема | Избыточно для реляционной модели Goal/Deposit |
