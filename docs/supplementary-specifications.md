\# Дополнительные спецификации системы GoalJar



В соответствии с методологией FURPS+, требования, не вошедшие в сценарии вариантов использования (Use Cases), зафиксированы в данном документе.



\## 1. Функциональность (Functionality)

\* \*\*Автономность:\*\* приложение работает без обязательного подключения к сети Интернет.

\* \*\*Хранение данных:\*\* локальное хранилище (файл JSON или база данных SQLite). Данные не передаются на сторонние серверы.

\* \*\*Валюты:\*\* базовая работа ведётся в одной валюте (например, BYN/RUB). Опционально (v1.1) — пересчёт цели в другую валюту через внешний HTTP API.

\* \*\*Резервирование:\*\* поддержка создания резервных копий файла базы данных (`.bak`) перед миграциями или обновлениями.



\## 2. Удобство использования (Usability)

\* \*\*Навигация:\*\* переход между ключевыми экранами («Сводка», «Экран цели», «Форма цели», «Форма пополнения») осуществляется максимум в 2 клика.

\* \*\*Язык интерфейса:\*\* русский.

\* \*\*Валидация:\*\* некорректный ввод (отрицательная сумма, дата в прошлом) блокируется с выводом понятного сообщения об ошибке рядом с полем.

\* \*\*Форматирование:\*\* денежные суммы отображаются с разделителями разрядов (например, `1 500 000.00`).

\* \*\*Контрастность:\*\* элементы интерфейса соответствуют стандарту доступности (контрастность ≥ 4.5:1).



\## 3. Надёжность (Reliability)

\* \*\*Отказоустойчивость:\*\* приложение не должно падать при повреждении файла данных — выводится сообщение об ошибке.

\* \*\*Атомарность записи:\*\* сохранение данных происходит атомарно (через временный файл с последующим переименованием, либо через транзакцию SQLite), чтобы избежать потери данных при внезапном отключении питания.

\* \*\*Стабильность:\*\* отсутствие утечек памяти при длительной работе (до 24 часов непрерывного использования).



\## 4. Производительность (Performance)

\* \*\*Время отклика:\*\* обработка клика по кнопке сохранения цели или пополнения занимает не более 300 мс.

\* \*\*Загрузка:\*\* главный экран загружается не более чем за 1 секунду при наличии до 100 активных целей.

\* \*\*Потребление ресурсов:\*\* потребление оперативной памяти процессом JVM не превышает 512 МБ (типовое значение < 200 МБ).

\* \*\*Холодный старт:\*\* запуск приложения с нуля занимает не более 3 секунд.



\## 5. Сопровождаемость и переносимость (Supportability)

\* \*\*Технологии:\*\* исходный код написан на Java 17 LTS; графический интерфейс реализован на JavaFX.

\* \*\*Архитектура:\*\* слоистая архитектура (UI → Services → Repository). Строгое разделение логики и интерфейса (MVC).

\* \*\*Кроссплатформенность:\*\* приложение запускается на Windows, Linux, macOS при наличии установленной JRE 17+.

\* \*\*Тестирование:\*\* бизнес-логика (расчёт прогресса, валидация) покрыта модульными тестами JUnit 5 (целевое покрытие ≥ 80%).
